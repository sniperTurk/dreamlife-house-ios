# DreamLife House v2.40.0 — build 60

## Data-loss and recovery fixes
- Fixed recovery ordering when a **newer compatible backup exists without any pending journal**. Previous builds could normalize the older primary and silently discard the newer progress. Now the backup is restored and retained.
- A malformed pending journal does not prevent recovery from a newer backup.
- When a newer pending journal replays, an intermediate backup is no longer replaced by an even older primary.
- Added optimistic concurrency guards for an externally changed primary, an externally staged newer journal, and a backup newer than the current in-memory sequence. Conflicting in-memory sessions enter read-only preview mode, protecting disk data. Same-sequence external edits are caught through byte comparison.
- Added a separate, accessible `save.externalChangeWarning` in RootView, distinct from future-schema warnings. Restarting the app reloads the latest on-disk state.

## iOS UI test preparation
- Added an XcodeGen `DreamLifeHouseUITests` UI-testing target and included it in the app's test scheme.
- Added UI tests for first-launch onboarding and future-save warning visibility.
- Added DEBUG-only isolated launch fixtures (`--dreamlife-ui-test-fresh`, `--dreamlife-ui-test-future`) that never touch production save keys.

## Regression coverage
- Added **6** XCTest source methods (195 → **201**).
- Added **19** runnable Linux model assertions (155 → **174**).
- Added **2** static UI wiring contracts (25 → **27**).

## Limitations
- Linux `swiftc -parse`, model typecheck, and smoke assertions do not verify SwiftUI iOS compilation.
- Linux SwiftPM XCTest auto-discovery crashes with actor-isolated XCTestCase methods in the existing test suite; real XCTest execution is not claimed.
- Real Xcode build, iOS Simulator UI tests, and physical iPhone/iPad validation still require macOS/Xcode.
- UserDefaults multi-key writes are not fsync-level atomic; optimistic guards do not make concurrent writes fully transactional.
