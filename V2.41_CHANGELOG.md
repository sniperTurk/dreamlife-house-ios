# DreamLife House v2.41.0 — build 61

## Adventure reward validation (gameplay fix)
- Moved the four House Adventure reward checks from disabled-button-only logic into `GameStore.claimAdventureTask(_:)`. A caller can no longer claim an unearned or unknown task, or supply an arbitrary coin reward.
- Reward amounts are fixed by the model: Party outfit +60, decoration +80, Rainbow Cupcake +100, and three living-room dances +120 coins. Each claim is one-time and persists across app restarts.
- The UI now calls the validated model action and exposes stable accessibility identifiers and stateful VoiceOver labels for each reward. Clarified that House Adventures are one-time challenges, separate from the daily chain.

## XCUITest readiness
- Added a DEBUG-only ready-to-claim dance fixture and a resume fixture that retains only the isolated UI-test save domain across app relaunches. Production save data remains untouched.
- Added an external-save-conflict fixture and UI test for its warning.
- Added an end-to-end XCUITest source case for claiming the dance reward, preventing a duplicate claim, and verifying that the earned currency and claim status survive app restart.
- Added a locked-reward UI test. Navigation helper supports iPhone's collapsed More tab when there are more than five tabs.
- Added an accessible coin balance identifier (`topbar.coins`).
