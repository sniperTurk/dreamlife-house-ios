# DreamLife House v2.37.0 — build 57

## Save-format compatibility and data-loss prevention
- **Fixed a save overwrite risk:** an explicit but malformed `schemaVersion` marker was previously interpreted as an old save in some recovery paths. Unknown markers are now protected rather than treated as legacy data.
- Rejects schema markers that are strings, `null`, JSON booleans, fractional numbers, zero, negative, or future integer versions. An **absent** schema marker remains compatible with genuine legacy saves.
- When the primary contains an unknown marker, the app enters read-only preview mode; a compatible backup may be displayed but neither primary nor backup is overwritten.
- When a compatible primary has a backup with an unknown marker, gameplay can continue while that backup remains untouched.
- If the save changes externally after the store loads (for example by restoring data from a newer app), the next write detects and protects it instead of overwriting it.
- Updated the warning text to explain both newer and unrecognized save formats.
