# DreamLife House v2.39.0 — build 59

## Stale-journal rollback prevention
- Added optional, monotonically increasing `commitSequence` to the existing Codable save format. Existing v2.38/legacy saves remain readable; no schema bump or destructive migration is required.
- Save commits now record the next sequence; loading an older pending journal cannot replace a newer committed primary. Equal-sequence, divergent pending data also favors the primary.
- When a known-good backup has a higher sequence than both primary and pending, startup recovery prefers the backup. The recovered backup is not overwritten by the first subsequent save.
- A genuinely newer pending journal still completes interrupted commits, and legacy unnumbered pending saves continue to recover.
- Negative or otherwise invalid commit sequences are rejected as invalid snapshots, without rolling back healthy data.

## Regression coverage
- Added 7 XCTest source methods (188 → 195): stale journal, equal-sequence conflict, newer journal replay, legacy replay, invalid negative sequence, sequence monotonicity across restart, and newer-backup recovery.
- Added 24 executable Linux model smoke assertions, bringing the aggregate model-smoke suite to **155 assertions** (69 + 15 + 24 + 23 + 24).
- Kept existing UI static-wiring checks and all prior gameplay regressions.

## Known limitations
- `UserDefaults` still does not provide fsync-level multi-key atomic transactions across unexpected device power loss.
- Linux `swiftc -parse` and model-source typechecking are not substitutes for Xcode builds or iOS XCTest execution.
- iOS Simulator, real iOS build and physical-device tests are pending a macOS/Xcode environment.
