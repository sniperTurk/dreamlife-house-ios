# DreamLife House v2.52.0 — build 72

## Recovery inspection and export consistency

- Previously the parent recovery preview and export independently read three UserDefaults slots. A second session could change the raw bytes after the parent had reviewed the preview but before the export; the export could silently include different contents.
- The Settings screen now starts an explicit `SaveRecoveryInspection` session. It displays bounded previews from a single captured three-slot snapshot. The model keeps the raw bytes private and issues an opaque UUID token.
- The parent-initiated export requires that token. The model compares **exact raw bytes** of all three slots against the inspected snapshot before creating the archive and re-reads them after encoding. Changes in fields not shown in the preview also invalidate export.
- An invalid or stale inspection produces a clear alert, removes the stale preview and disables export until the parent explicitly selects **Refresh save inspection**. Refresh invalidates the previous token even when bytes are unchanged.
- No save candidate is chosen, merged, overwritten, or uploaded. Existing untokened export API remains available for previous programmatic tests; the user-facing UI exclusively uses the token-checked method.
- Original, independent gameplay and graphics are preserved; no third-party characters or assets were added.
