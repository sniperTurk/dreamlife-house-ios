# DreamLife House v2.35.0 — build 55

## P0 data-loss prevention
- Fixed a future-version save compatibility issue: the v2.34 loader would overwrite a primary save with `schemaVersion > currentSaveSchemaVersion` using an older backup, despite claiming to protect newer saves. This could permanently erase progress added by the newer app.
- Detect the newer schema before backup recovery and enter `isSaveReadOnlyDueToNewerVersion` mode. A compatible backup is only loaded as an in-memory preview. All writes, including reset, reward, and normalized-load writes, are blocked for that session. The original future primary and backup remain byte-for-byte intact.
- Show an accessible banner on the root screen explaining that changes cannot be saved until the app is updated. Corrupt/legacy compatible saves continue their normal writable recovery path.
