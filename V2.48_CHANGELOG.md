# DreamLife House v2.48.0 — build 68

## Parent-only, read-only save-conflict previews
- Settings now displays separate **Primary**, **Backup**, and **Pending** copy summaries only while the game has detected an ambiguous, equal-sequence save conflict.
- Each readable copy shows its journal sequence (or `legacy`), bounded coin and star balances, and number of completed tasks. Missing, damaged, and newer/unrecognized save formats receive distinct status messages. Player names, save JSON and other personal details are not shown in the preview.
- The preview never selects a winner, imports, merges, deletes, or writes a save. It double-reads the three slots to avoid knowingly showing a mixed snapshot if another session changes them during inspection.
- Existing parent-initiated raw export and v2 CRC32 integrity verification are preserved. All original, distinct save candidates remain untouched.
- Five new model XCTest source cases cover healthy saves, the conflict summaries, malformed candidates, future schemas and extreme numeric values. A new XCUITest source case checks the parent-facing UI. A new 25-assertion Linux smoke suite and six static wiring checks were added.
- Original, family-friendly game content remains unchanged; no third-party brands or licensed characters/assets were introduced.

## Known limitations
- Preview totals are advisory only. A readable save does not establish that it is the *correct* winner. The user must preserve and evaluate conflicting copies manually; no automatic restore/merge exists.
- Reading twice reduces but does not eliminate concurrent mutation risk; UserDefaults is not an atomic, multi-key transactional database.
- Actual Xcode/iOS build, XCTest, XCUITest, Simulator and physical iPhone/iPad tests remain unrun in this Linux environment.
- Previously planned gameplay feature completion stays **100% (+0 percentage points)**; this is not App Store release certification.
