# DreamLife House v2.46.0 — build 66

## Parent-controlled, lossless recovery export
- Added a **Save recovery · for parents** section in Settings, shown only when the app detects an ambiguous save conflict. A parent can export the preserved save candidates using iOS's system Files exporter.
- `GameStore.exportAmbiguousRecoveryArchive()` builds a deterministic JSON archive containing the **raw** `primary`, `backup`, and `pending` slots as Base64 bytes, including missing or malformed primary data. Archive format v1 identifies the `ambiguous-equal-sequence` reason. The method returns `nil` for normal, writable saves.
- Export reads each slot twice and declines to export if bytes change during preparation. Export never writes to, deletes, or selects a winner among the on-device save candidates; the game remains read-only after export.
- The UI explains that recovery archives contain local gameplay data and should only be shared with a trusted adult. The system document picker requires an explicit destination choice; there is no automatic upload or import.
- Added `SaveRecoveryDocument.swift`, four XCTest source methods, one XCUITest source method and a new Linux-executable smoke suite. Static UI wiring now checks the export path.
- Version/build updated to 2.46.0 / 66. Save schema remains 4; no migration required. The content and characters remain original.

## Known limitations
- Export is **not** conflict resolution or a restore/import workflow. A parent must keep the exported file for possible later recovery; gameplay changes still cannot be saved while ambiguity remains.
- SwiftUI's document exporter and actual iOS XCTest/XCUITest are not executable in this Linux environment. A macOS/Xcode build and iPhone/iPad tests are required before release.
- The prior planned feature scope remains 100% (+0 percentage points); this does not imply App Store readiness.
