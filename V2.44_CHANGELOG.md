# DreamLife House v2.44.0 — build 64

## Fix: terminal save-journal sequence must not overflow or lose progress
- Fixed a v2.43 defect where `commitSequence == Int.max` was rejected as an invalid save. A valid terminal primary, pending commit or backup is now decoded and recovered without reverting to older progress.
- Added a fail-closed write guard: once the terminal sequence is committed, further saves leave the on-disk bytes untouched and display a visible, accessible warning. This is intentionally read-only; sequence wraparound would break recovery ordering.
- Opening a save at `Int.max - 1` no longer consumes its final available journal sequence during automatic load normalization. One final gameplay commit is permitted and verified.
- Added a dedicated DEBUG-only UI fixture and XCUITest source case for the terminal warning.
- Added four model XCTest methods and 19 executable Swift model smoke assertions covering primary, pending, backup and last-commit scenarios.
- Version/build updated to 2.44.0 / 64. Save schema remains 4 and no migration is required.

## Scope and limitations
- **Planned feature completion:** 100% (+0 percentage points from v2.43). This is a hardening release, not a new feature-scope milestone.
- iOS build, actual XCTest, iOS Simulator and physical-device testing require macOS/Xcode and remain unverified.
- Normal gameplay never approaches `Int.max` commits; the read-only guard is designed for extreme or manually restored data. If reached, preserving the save is prioritized over additional writes.
- No third-party character, branding, art or other copyrighted assets added.
