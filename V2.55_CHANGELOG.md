# DreamLife House v2.55.0 — build 75

## Safer interleaved save writes

- Guard against overwriting any pending journal that another session left after this GameStore was loaded. Equal-sequence primary/pending and primary/backup conflicts still use the more specific ambiguous-recovery lock.
- Revalidate primary and backup immediately after writing our own pending journal. If another session changed either slot during the stage, stop before backup rotation or primary commit, and enter external-change read-only mode.
- Recheck primary, backup and pending after backup rotation and immediately before the primary commit. Preserve external primary and pending bytes when interleaving is detected.
- On an aborted commit, clean up only the pending journal whose bytes still match our own stage; never delete a different pending payload.
- Keep legacy startup cleanup for an invalid/non-future journal when a readable committed save exists and there is no ambiguous conflict. This preserves historical recovery tests.
- Five new XCTest source tests and one isolated Linux Swift smoke suite (24 assertions) simulate writes during pending staging and backup rotation.
- All gameplay, names and visuals remain original; no third-party franchise assets were introduced.

## Limitations

UserDefaults offers no atomic cross-process transaction or compare-and-swap. A competing write between the final comparison and the actual primary write remains possible. The rollback of our own pending journal is also best-effort. File-based transactional persistence is a candidate for a future major revision. No save conflict is automatically merged or selected.
