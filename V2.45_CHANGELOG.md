# DreamLife House v2.45.0 — build 65

## Save recovery: ambiguous equal-sequence conflict is read-only
- Fixed a v2.44 recovery ambiguity: if a valid pending journal and valid backup have the **same positive commit sequence but different bytes**, and the primary is missing, corrupt, or older, the old recovery path could replay the pending copy over the committed backup without being able to prove which was newer.
- The app now previews the committed backup **without changing any on-disk candidate** (primary, backup or pending). It sets `isSaveReadOnlyDueToAmbiguousRecovery` and blocks further persistence until the conflict is resolved. No guess about the winning copy is silently committed.
- A prominent, VoiceOver-addressable banner explains that the copies were preserved and new progress cannot be saved. A DEBUG-only isolated UI fixture and XCUITest source case exercise the warning.
- Normal cases are unchanged: a strictly newer pending journal still replays; byte-identical pending/backup can replay; a valid committed primary at the same sequence remains authoritative; older unnumbered legacy journals follow their existing compatibility path.
- Added five XCTest source methods and a Linux-executable model smoke suite covering missing, older and corrupt primaries; distinct and identical equal-sequence snapshots; strictly newer pending; and committed primary priority.
- Version/build updated to 2.45.0 / 65. Save schema remains 4; no migration is required.

## Limitations
- Ambiguous conflicts deliberately remain unresolved on disk; recovery requires a later conflict-resolution workflow or manual backup analysis. The UI is read-only in that rare case to prevent further data loss.
- The in-memory preview may differ from the pending candidate. Neither candidate is discarded.
- Planned feature scope remains 100% (+0 percentage points versus v2.44). This is a safety/test release, not evidence of App Store readiness.
- Linux Swift model execution and static source validation are not iOS build, XCTest, Simulator or physical-device verification.
- All game names, characters and assets remain original; no third-party brand art or copyrighted game content was added.
