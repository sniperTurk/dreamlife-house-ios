# DreamLife House v2.49.0 — build 69

## Preserve equal-sequence primary/backup conflicts without a pending journal
- Fixed an additional save-data loss path: when the primary and backup are both readable and have the **same positive journal sequence but different bytes**, with no pending journal, loading no longer silently accepts and normalizes the primary over the backup. Instead it presents the primary as a **read-only preview** and keeps both original copies untouched.
- A running game session now re-checks the same conflict immediately before staging a new save. This prevents an externally edited equal-sequence backup from being overwritten while the game is open.
- Existing safety behavior is preserved: identical copies are not treated as conflicts; an older backup remains eligible for normal gameplay; invalid backups do not cause a false equal-sequence conflict. The previous pending/backup conflict behavior remains unchanged.
- Parent-facing recovery preview/export now works for this additional conflict shape: **Primary, Backup, Pending (absent)**, with no import, merge, selection, or automatic deletion.
- Added five XCTest source cases, one XCUITest source case with an isolated DEBUG fixture, and a 26-assertion executable Linux smoke suite. Expanded static UI wiring checks.

## Limitations
- Equal sequence and differing bytes is a conservative conflict signal, not evidence of tampering. The preview is **not** a verified winner and does not resolve the conflict.
- UserDefaults has no atomic cross-key transaction guarantee; the double-read export and pre-save checks reduce but do not eliminate races.
- This Linux environment cannot run a real iOS build, XCTest runtime, iOS Simulator, or physical iPhone/iPad tests.
- **General completion: 100% of planned gameplay scope (+0 percentage points).** App Store release readiness is not certified.
