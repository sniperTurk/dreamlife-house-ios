# DreamLife House v2.47.0 — build 67

## Recovery archive integrity validation
- New parent-initiated recovery exports use **format v2**. Each of the three raw save slots (`primary`, `backup`, `pending`) includes a CRC32 checksum and byte count; absent slots use the distinct `absent` marker. Original bytes remain unchanged.
- The export path validates the archive and its JSON encode/decode round-trip before offering the Files picker. The save remains read-only during an unresolved conflict.
- Format v1 archives can still be decoded, but their integrity status is `legacyUnverified`. Unknown versions, missing/duplicated/reordered slots, invalid reasons, missing checksums and altered bytes fail validation.
- Added `Tools/verify_recovery_archive.py` to check exported JSON files **offline**, with no cloud transfer or output of save contents. Exit code 0 = verified v2, 2 = unverified legacy v1, 1 = invalid.
- Added five XCTest source cases, one XCUITest source case, a Swift smoke suite with 25 assertions, and twelve Python verifier regression tests. A cross-language test verifies a real Swift-generated export using the Python checker.
- Parent-facing Settings text now clarifies that the archive is not encrypted or tamper-proof. CRC32 detects accidental damage but does **not** authenticate the source or prevent intentional modification.
- No game assets or licensed third-party characters are used; original game content is unchanged.

## Limits
- This is a verification and preservation workflow, not a recovery import or automatic conflict merge. No recovery candidate is overwritten or selected by export.
- No real Xcode/iOS build, XCTest run, simulator test or physical iPhone/iPad test could be performed in the Linux environment.
- The previous feature-scope completion remains 100% (+0 percentage points). Release readiness is not certified.
